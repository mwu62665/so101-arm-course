六大功能锚点 F0–F5

一、核心功能验收锚点（按可观测物理标准阶梯解锁） F0 硬件前提 → F2 基础闭环 → F3 核心突破 → F4/F5 综合验收
F0 关键前提
本体可用
单臂装好、通电、6 关节可控且稳定通信。
判定：通电通信正常、手柄遥控响应平滑且关节角读数连续。
F1 前提
感知定位
双相机手眼标定 + YOLO 桌面检测跑通。
判定：稳定检测杯具，坐标误差落在夹爪容差内。
F2 基础闭环
程序化抓取闭环
规则物体「识别→定位→抓取→放置」全链路。
判定：固定位姿重复抓放跑通，零训练、稳且快。
F3 核心突破
ACT 模仿学习
手柄遥操作采示教 → 训练策略 → 视觉自主抓取。
判定：对未示教过的杯子摆放位置可实现泛化抓取。
F4 验收
场景闭环
桌面杯具与餐具连续归位整理整段流程。
判定：连续完成「识别→抓取→归位」，肉眼可验。
F5 验收
语言指令
自然语言 → 受约束结构化任务 → 驱动执行。
判定：说一句话准确路由任务，不碰图像、无 VLM。
二、项目规范管理与透明公示机制 全员可见 · 过程留痕 · 权责明晰
1. 双轨进度与阻塞公示
进度公示.md / 本周工作安排.md
按周同步全员在办事项、完成判定与已办结清单；特设「卡住的事」公开看板，写明阻塞责任人、依赖项与截止日，杜绝隐性延期。
2. 财务与采购全透明台账
资金管理.md / 采购清单.md
坚持自愿垫资原则，公开 10 人垫资明细、每笔物料型号、单价、商品链接与资金结余，下学期报销款到账后按台账原路返还。
3. 重大架构决策留痕可回溯
变更记录.md + Git 版本控制
所有范围与架构变更（架构定型、硬件选型、分工调整）均记录日期与原因；历史方案完整保留在 Git 提交中，随时可回滚。
4. 代码分区与知识产权共享
GitHub 开源协作仓库
仓库按 docs/、host/、training/、firmware/ 模块化协作；全部代码、数据集与文档全员共享，机械臂作为组内开放实验平台。
