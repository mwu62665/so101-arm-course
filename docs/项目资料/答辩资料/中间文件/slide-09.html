08 // TOP-LEVEL LLM · LIGHTWEIGHT COMMAND PARSER

顶层 LLM 只做「受约束指令解析」，不碰图像、不做 VLM / VLA

验收锚点 F5
1–2 周可出稳定 Demo，严控幻觉风险
指令翻译与安全校验示例 Natural Language → JSON
USER VOICE / TEXT INPUT
“先帮我把桌面上的红杯子放进杯架，再把餐盘归位到右侧区。”
↓ 轻量 LLM 解析 + 受约束 Schema 校验（白名单过滤） ↓
// 输出受约束结构化任务队列（仅允许白名单动作与物体） { "status": "VALID", "tasks": [ { "step": 1, "action": "pick_and_place", "target": "red_cup", // 路由 → ACT 策略 "zone": "cup_rack" }, { "step": 2, "action": "pick_and_place", "target": "plate", // 路由 → YOLO 程序化 "zone": "plate_zone" } ] }
安全兜底：若用户要求“帮我切水果”或缺少目标区域，校验层直接拦截拒绝或触发澄清反问，绝不向底层发送非法指令。
明确能做到（交付范围） IN SCOPE
  • 意图结构化翻译：自然语言 → 动作、目标类别、终点区域标准 JSON。
  • 多步任务编排：拆解先后顺序与重复次数（先收杯子，再放餐盘）。
  • 参数补全与澄清：缺目标区域时主动反问，补全默认速度等安全参数。
  • 白名单安全约束：词表之外的物体或危险动作一律直接拒绝。
系统能力边界（非本模块职责） OUT OF SCOPE
  • 不直接看图、不做视觉定位：“红杯子在哪”由 YOLO + 双相机负责，不涉及 VLM。
  • 不生成关节轨迹、不控舵机：运动控制完全交由底层程序化轨迹或 ACT 执行。
  • 不识别词表外新物体，不保证物理成败：物理抓取成功率取决于检测、标定与示教质量。
  • 防幻觉强制校验：LLM 输出必须过结构化校验器，禁止直连执行层。
ONE-LINE ROLE LLM 在本项目中的定位是“解析自然语言、下发受约束结构化指令的调度层”，而非“看图干活的通用端到端大模型”。
